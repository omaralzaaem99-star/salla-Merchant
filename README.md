**اقرأ [متابعة النشر والتحقق — 13 أكتوبر](RELEASE_A7_A9_AR.md) مع [تقرير التدقيق الأصلي](AUDIT_AR.md) قبل الإصدار.** نُشرت إصلاحات الخادم والقواعد وتصحيح فقرة إنشاء الحساب في السياسة وتحققت على الإنتاج. الحزمة ليست إعلان جاهزية أو ضمان قبول Apple؛ نُشر تحديث التبعيات الأمني في متابعة DEPENDENCY_RELEASE_AR.md. بقي قرار الاحتفاظ باسم المتجر ومعرّفاته، وحماية القراءة الإرثية، واختبار iPhone/iPad والتوقيع.

## المحتويات

- `sala_store`: سورس التطبيق وملفات Android وiOS والأصول والاختبارات.
- `packages/salla_auth` و`packages/salla_data`: الحزمتان المحليتان المطلوبتان؛ أبقهما بجانب مجلد التطبيق.
- `SOURCE_MANIFEST.json`: بصمات ملفات السورس الأصلية للتحقق من تطابقها.

## آخر تعديل

سورس التدقيق يضيف تنظيف تلميحات الدخول بعد الحذف، وإصلاح ترتيب تسجيل APNs/FCM، وإعادة محاولة بدء التشغيل. إصلاحات الخادم لتنظيف بقايا بيانات الاتصال والموقع، ومنع إعادة تقديم الحساب بهوية محذوفة، والحد من تخمين رمز الدخول نُشرت وتحققت في متابعة 13 أكتوبر. أُصلح أيضاً تصنيف رفض الجلسة المحذوفة واجتاز اختبار إنتاج مخصص. اسم المتجر والسجلات المرتبطة باقية مؤقتاً بقرار المالك؛ لا نعدها بيانات مجهولة ولا نعلن اكتمال امتثال الحذف قبل حسمها. نشر الخادم لا يحدّث بناء التطبيق المرسل سابقاً إلى Apple.

الاستكشاف وإنشاء الحساب وموافقة الإدارة والتواصل مع الدعم وبقية ميزات التطبيق موجودة في هذا السورس.

## التشغيل

الأدوات المستخدمة: Flutter 3.44.0 وDart 3.12.1. افتح جذر المستودع في VS Code ثم:

```sh
cd sala_store
flutter pub get
flutter run --flavor prod --dart-define=SALLA_ENV=prod --dart-define=SALLA_DATA_BACKEND=firebase
```

الأمر أعلاه لأندرويد. معرّف إنتاج Android: `com.salasala.marchent`.

لبناء Android الموقّع تحتاج مفتاح التوقيع وملف الإعداد المحلي `~/.selafood/signing/store.properties`، بحقول `storeFile` و`storePassword` و`keyAlias` و`keyPassword`. تُسلّم بيانات التوقيع بصورة منفصلة وآمنة. ثم:

```sh
flutter build appbundle --release --flavor prod --dart-define=SALLA_ENV=prod --dart-define=SALLA_DATA_BACKEND=firebase
```

## iOS وشركة النشر

معرّف الإنتاج: `com.salllla.marchent`. المشروع يستخدم Flutter Swift Package Manager؛ الملفات المؤقتة وحزم الإضافات تُولّد على جهاز البناء. على macOS مع Xcode وإعداد فريق التوقيع:

```sh
cd sala_store
flutter pub get
flutter build ipa --release --dart-define=SALLA_ENV=prod --dart-define=SALLA_DATA_BACKEND=firebase
```

إعدادات Firebase الأصلية مرفقة، ويختار Release إعداد الإنتاج. لا تغيّر Bundle ID أو إعدادات Firebase عند تجهيز رفع النسخة. لم يُبنَ أو يُرفع إصدار iOS لهذه النسخة من بيئة Windows؛ يلزم بناؤه واختباره على iPhone لدى شركة النشر قبل التقديم إلى Apple.

## نطاق التسليم

المستودع خاص بتطبيق المتجر واعتماداته المحلية. وظائف الخادم وقواعد Firebase ولوحة الإدارة تعتمد على بيئة الإنتاج القائمة `sela-food-prod`، وليست جزءاً من هذا المستودع. إعدادات Firebase المرفقة إعدادات عميل التطبيق، وليست بيانات دخول إدارية. لا يحتوي التسليم على بيانات المستخدمين أو مفاتيح التوقيع أو حسابات الخدمة أو مخلفات البناء.

اختبارات تدفق الحذف والخادم وقواعده وبوابتا المتاجر والتوزيع نجحت في مساحة المشروع؛ كما بُني وثُبت Android 1.0.1+30. اختبار صاحب الحساب على حساب مخصص للحذف وتسجيل فيديو مراجعة Apple يبقيان خطوة منفصلة؛ لم يُحذف حساب إنتاجي بغرض اختبار هذا التسليم.
